# تیزنت — حساب‌دفتر من

> نام برنامه: **تیزنت**. نام بستهٔ داخلی اندروید (`applicationId`) عمداً همان `ir.cmbtools.ledger` مانده تا
> آپدیت‌ها روی نسخهٔ قبلی نصب شوند و داده‌های مالی پاک نشوند.

اپلیکیشن اندرویدی **شخصی** برای فروشندگان سرویس اینترنت: حساب‌دفتری مشتریان، صدور فاکتور،
اتصال به پنل **هیدی‌فای ۱۴** (ساخت/تمدید اکانت با یک کلیک)، ارسال فاکتور با پیامک،
خواندن **پیامک بانکی** و تطبیق خودکار پرداخت با فاکتور/مشتری، و گزارش‌های مالی فارسی.

محدوده: **استفادهٔ شخصی، تک‌گوشی، بدون بک‌اند، نصب مستقیم (APK)** — بدون نیاز به Google Play.
به همین دلیل قابلیت خواندن پیامک بانکی به‌صورت کامل فعال است.

### نسخه‌بندی

هر آپدیت شمارهٔ نسخهٔ خودش را دارد و همین شماره داخل برنامه (**تنظیمات ← درباره**) و در عنوان
ریلیز گیت‌هاب دیده می‌شود. قاعدهٔ افزایش نسخه در `app/build.gradle.kts`:

| نوع تغییر | `versionName` | `versionCode` |
|-----------|---------------|---------------|
| تغییر بزرگ / ناسازگار | `1.0.0` | +۱ |
| قابلیت جدید | `0.x.0` | +۱ |
| رفع اشکال | `0.x.y` | +۱ |

`versionCode` باید در هر انتشار **حداقل یکی** بیشتر شود، وگرنه اندروید اجازهٔ نصب روی نسخهٔ قبلی را نمی‌دهد.

اسناد طراحی و امکان‌سنجی: [`docs/feasibility-report-fa.md`](docs/feasibility-report-fa.md)
و معماری/راهنمای فنی: [`docs/tech-fa.md`](docs/tech-fa.md)

🔌 **بررسی کامل API هیدی‌فای ۱۴** (مسیرها، شکل پاسخ‌ها و اشکالاتی که «ساخت کاربر» و
«همگام‌سازی» را می‌شکست): [`docs/panel-api-v14-fa.md`](docs/panel-api-v14-fa.md)

## ساخت APK

پیش‌نیاز: Android Studio (Ladybug یا جدیدتر) یا JDK 17 + Android SDK 34.

```bash
# ۱) باز کردن پروژه در Android Studio و Sync Gradle
# ۲) اجرا روی گوشی/امولاتور
./gradlew assembleDebug

# ۳) نسخهٔ نهایی (برای استفادهٔ شخصی، با keystore خودتان امضا کنید)
./gradlew assembleRelease
```

خروجی: `app/build/outputs/apk/`.

اگر فایل `gradlew` را ندارید، یک‌بار در Android Studio گزینهٔ *Sync Project* را بزنید یا:

```bash
gradle wrapper --gradle-version 8.7
```

> پروژه با **Gradle Wrapper** کامل (`gradlew` / `gradlew.bat` / `gradle-wrapper.jar`) همراه است؛
> نیازی به نصب جداگانهٔ Gradle یا Java نیست. اگر از خط فرمان اجرا می‌کنید، از `gradlew.bat` (ویندوز)
> یا `./gradlew` (مک/لینوکس) استفاده کنید.

### نکتهٔ مهم امضا

همیشه با **یک keystore ثابت** امضا کنید؛ اگر امضا عوض شود، آپدیت روی نسخهٔ قبلی نمی‌نشیند و
دادهٔ محلی (دفتر مالی) پاک می‌شود. قبل از هر آپدیت، از صفحهٔ گزارش‌ها «پشتیبان کامل» بگیرید.

## راه‌اندازی اتصال پنل

1. در پنل هیدی‌فای: **تنظیمات ← تنظیمات خیلی پیشرفته** و مقدار **مسیر پروکسی مدیران** را بردارید.
2. کلید API = **UUID ادمین** (از صفحهٔ ادمین‌ها/لینک پنل).
3. در اپ: **تنظیمات ← اتصال به پنل** → دامنه (بدون `https://`)، مسیر پروکسی، کلید API → «ذخیره و تست».

اندپوینت‌های استفاده‌شده (نسخهٔ ۱۴):

```
GET    /<proxy>/api/v2/panel/info/          تست اتصال و نسخهٔ پنل
GET    /<proxy>/api/v2/admin/users/         لیست کاربران + link_domains
POST   /<proxy>/api/v2/admin/users/         ساخت کاربر
PATCH  /<proxy>/api/v2/admin/users/{uuid}/  تمدید دورهٔ جدید / فعال‌سازی
POST   /<proxy>/api/v2/admin/users/bulk/    افزودن حجم و روز (add_limits)
```

هدر: `Hiddify-API-Key: <uuid ادمین>`

## فاکتور خودکار (بدون کار دستی)

اپ دو حالت را خودش تشخیص می‌دهد و فاکتور می‌سازد؛ لازم نیست هر بار فرم پر کنید:

| رویداد | اپ چه می‌کند |
|--------|----------------|
| اکانت جدید در پنل (ساخته‌شده داخل اپ یا مستقیم در پنل) | فاکتور «اکانت جدید» + پیامک فوری به شمارهٔ ثبت‌شده |
| تمدید اکانت (جلو رفتن تاریخ انقضا در پنل) | فاکتور «تمدید» + پیامک فوری |
| افزایش حجم/روز (add_limits) | فاکتور نمی‌سازد (تمدید محسوب نمی‌شود) |

**هر ۵ دقیقه** یک سرویس پس‌زمینه با پنل همگام می‌شود (اعلان کوچک و کم‌اهمیت در نوار وضعیت).
از **تنظیمات ← همگام‌سازی و فاکتور خودکار** می‌توانید خاموش کنید، فاصله را ببینید،
و «شمارهٔ کارت» و «قیمت هر گیگ» را تنظیم کنید.

### مانده قبلی و جمع کل بدهی

اگر مشتری از قبل بدهکار باشد، در همان فاکتور نمایش داده می‌شود:

```
مانده قبلی: ۸۰۰٬۰۰۰ ریال
جمع کل بدهی: ۲٬۳۰۰٬۰۰۰ ریال
```

این اعداد به‌صورت «عکس فوری» روی فاکتور ذخیره می‌شوند؛ بعداً با ثبت پرداخت یا تغییر
قیمت بسته‌ها، متن فاکتور قبلی عوض نمی‌شود.

### ساختار پیامک فاکتور

```
<نام کسب‌وکار>
فاکتور 1405-0042
مشتری: علی رضایی
تاریخ: ۱۴۰۵/۰۸/۰۳ - ۱۴:۳۵
بسته: یک‌ماهه ۳۰ گیگ
مبلغ: ۱٬۵۰۰٬۰۰۰ ریال
مانده قبلی: ۸۰۰٬۰۰۰ ریال
جمع کل بدهی: ۲٬۳۰۰٬۰۰۰ ریال
کارت: 6037-9977-1234-5678
لینک اشتراک: ...
```

متغیرهای قابل استفاده در قالب (تنظیمات ← پیامک):
`{business} {customer} {invoiceNo} {datetime} {date} {package} {items} {total} {prevBalance} {totalDebt} {debt} {card} {kind} {link} {footer}`

## نحوهٔ استفاده (جریان روزمره)

1. **مشتریان** → افزودن مشتری (نام، موبایل، ۴ رقم آخر کارت برای تطبیق پیامک).
2. **فاکتور** → دکمهٔ + → انتخاب مشتری و بسته → دکمهٔ «صدور فاکتور».
   - اگر «ساخت اکانت در پنل» روشن باشد، اکانت ساخته می‌شود و لینک اشتراک روی فاکتور می‌نشیند.
   - اگر «ارسال با پیامک» روشن باشد، متن فاکتور + لینک برای مشتری ارسال می‌شود.
3. **پیامک بانکی** هنگام واریز خودکار خوانده می‌شود:
   - اگر مبلغ با ماندهٔ فاکتور و ۴ رقم کارت بخواند → خودکار تسویه می‌شود.
   - وگرنه در تب «بانک» می‌ماند و با انتخاب مشتری، دستی تخصیص می‌یابد.
4. **گزارش‌ها** → مطالبات، سنی بدهی، سود/زیان، خروجی Excel و پشتیبان.

## هشدارها

- کلید API پنل روی گوشی ذخیره می‌شود (رمزنگاری‌شده با Keystore). گوشی را قفل‌دار نگه دارید.
- اپ فقط پیامک‌هایی را پردازش می‌کند که الگوی «واریز» دارند؛ بقیه نادیده گرفته می‌شوند،
  اما مجوز SMS در سطح سیستم به کل صندوق پیامک دسترسی می‌دهد.
- پیامک بانکی قابل جعل است؛ برای مبالغ بالا آستانهٔ «تأیید دستی» را در تنظیمات پایین نگه دارید.
- پشتیبان‌گیری دوره‌ای را جدی بگیرید: تنها نسخهٔ داده روی گوشی است.
