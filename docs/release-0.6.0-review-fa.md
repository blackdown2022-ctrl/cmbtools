# بررسی و راهنمای قابلیت «ربات» — نسخهٔ ۰.۶.۰

## نتیجهٔ بررسی پروژهٔ پیوندشده

مخزن `tiznetvpn-lang/salebot` بررسی شد. در clone بررسی‌شده، commit برابر `124d5fb867e3b06e3a60d7d05bc49ea9e4c10c8c` و نسخهٔ اعلام‌شده `1.8.37-ubuntu26.39` بود. این پروژه یک فروشگاه/ربات تلگرام self-hosted است و بخش «اتصال اپ شتاب» را در سمت سرور دارد؛ برای این قابلیت لازم نیست endpoint جدیدی روی سرور نوشته شود.

قرارداد مصرف‌شده در اپ:

- سلامت: `GET https://<دامنه>/wp-json/webdide-cv/v1/health`
- تأیید: `POST https://<دامنه>/wp-json/webdide-cv/v1/confirm`
- احراز هویت: هدر `Authorization: <Secret>`
- بدنهٔ تأیید: `{"amount":<تومان>,"recipeId":"<کد پیگیری>"}`
- مبلغ یکتا باید دقیقاً با سفارش باز جور باشد. اپ مبلغ پیامک را که در واحد ریال است فقط اگر بر ۱۰ بخش‌پذیر باشد به تومان تبدیل می‌کند.

سرور مبلغ را با سفارش باز تطبیق می‌دهد، مورد تکراری را idempotent پاسخ می‌دهد، مبلغ مبهم/بدون سفارش را خودکار تأیید نمی‌کند و پس از ثبت پرداخت، فرایند تحویل سفارش را اجرا می‌کند. پیامکِ بانک ناشناس یا فاقد کد پیگیری را اپ نمی‌فرستد. درخواست‌های شبکهٔ موقت با WorkManager تا ۵ بار و با فاصلهٔ افزایشی تکرار می‌شوند؛ Secret در دادهٔ WorkManager قرار نمی‌گیرد و هنگام اجرا از فضای امن خوانده می‌شود.

مخزن ربات مجوز اختصاصی (All Rights Reserved) دارد؛ کد آن در اپ کپی یا توزیع نشده و فقط API مستندش مصرف می‌شود. در clone بررسی‌شده، `npm test` و `npm run check` هر دو موفق شدند.

## محدودیت مهم تأیید

این اتصال **استعلام مستقل بانکی نیست**. API ربات از اپ فقط مبلغ و کد پیگیری می‌گیرد؛ شمارهٔ کارت مقصد را از درخواست نمی‌گیرد و تراکنش را مستقیماً از بانک استعلام نمی‌کند. بنابراین نتیجه، «تطبیق پیامک واریز با مبلغ یکتای سفارش» است، نه اثبات مستقل بانکی یا تضمین این‌که پول به کارت مشخصی رسیده است. فقط روی گوشی/سیم‌کارتی فعالش کنید که برای پیامک‌های کارت فروشگاه اختصاص داده‌اید؛ اگر گوشی پیامک کارت‌های دیگری را هم می‌گیرد، آن واریزها هم ممکن است بررسی/ارسال شوند.

## راه‌اندازی

1. در پنل نصب شخصی ربات، بخش **تنظیمات ← اتصال اپ شتاب** را باز و Secret بسازید/کپی کنید؛ همچنین مطمئن شوید کارت‌به‌کارت خودکار روی سرور روشن و تنظیم شده است.
2. در داشبورد اپ، **ربات** را باز کنید. آدرس HTTPS نصب خودتان را وارد کنید (ریشهٔ دامنه یا مسیر کامل `/wp-json/webdide-cv/v1/confirm`) و Secret را بچسبانید.
3. «ذخیرهٔ رمزگذاری‌شده» را بزنید، سپس «آزمایش اتصال» را اجرا کنید. فقط پاسخ سلامت موفق سرور وضعیت اتصال را سبز می‌کند.
4. تنها پس از موفقیت آزمایش و اطمینان از اختصاصی‌بودن سیم‌کارت، کلید «تأیید خودکار ربات» را روشن کنید. هر زمان لازم بود از همین صفحه خاموشش کنید.

Secret در `EncryptedSharedPreferences` و با Keystore اندروید نگه‌داری می‌شود. عمداً به فایل JSON پشتیبان صادر نمی‌شود؛ پس از بازیابی پشتیبان، اتصال ربات خاموش است و باید Secret را دوباره وارد کنید. آدرس URL در تنظیمات پشتیبان می‌ماند.

## قواعد ارسال و پیام نتیجه

- فقط SMS بانکیِ مبلغ‌دار، اعتباری، غیر OTP، غیر برگشتی، از بانک شناخته‌شده و دارای کد پیگیری به صف سرور می‌رود.
- برداشت، OTP، برگشت وجه، مبلغ نامعتبر، بانک ناشناس و SMS بدون کد پیگیری ارسال نمی‌شوند.
- پیام «واریز تأیید شد» فقط با پاسخ موفق API که تأیید پرداخت را صریحاً اعلام کند نمایش داده می‌شود. قطع اینترنت، timeout، خطای API یا «سفارش پیدا نشد» تأیید محسوب نمی‌شود.
- ثبت پرداخت و تحویل سفارش دو نتیجهٔ جدا هستند؛ اگر سرور پرداخت را ثبت کند ولی تحویل ناموفق باشد، اپ هر دو را از هم تفکیک و پیگیری مدیر ربات را یادآوری می‌کند.
- آزمایش اتصال فقط سلامت endpoint و Secret را می‌سنجد؛ هیچ پرداخت آزمایشی ارسال نمی‌کند.

## بررسی‌های نسخه

- تست واحد افزوده‌شده: پذیرش/رد SMS برای ارسال به ربات بر اساس بانک شناخته‌شده، کد پیگیری، برگشت وجه و قواعد parser.
- نسخه: `0.6.0`، کد نسخه: `12`.
- ساخت نهایی APK و تست‌های Gradle باید در GitHub Actions انجام و نتیجهٔ workflow قبل از انتشار بررسی شود.
